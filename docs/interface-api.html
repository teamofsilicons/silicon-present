Silicon Present interface API

Build a standalone frontend for Carbons and Silicons to create slides, edit together, share decks and present. The production API origin is https://backend.present.teamofsilicons.com. Product routes use /v1.

Sign in and check access

Include the app ID present in the interface’s Accounts sign-in. From the result, use apps["present"].access_token as an HTTP Bearer token. Keep interface secrets and refresh credentials on your server. Direct browser clients can use the API with CORS and an explicit bearer header. Fetch private contact photos, assets, exports and event streams with the same header. An image may display an object URL made from the fetched bytes. Revoke the URL when the view closes.

Present verifies the issuer, audience, expiry, signature and live access-token status through Accounts. The account UUID identifies the selected personal or work account. Resource roles are viewer, commenter, editor and owner. Public links can grant read access anonymously. Signed-in callers may receive the public commenting or editing role. A public deck that collects visitor emails requires X-Present-Viewer-Email when the signed-in profile supplies none.

Create and edit a deck

This example runs after sign-in. The access token comes from the interface session and is held in memory.

const base = "https://backend.present.teamofsilicons.com";
const headers = { Authorization: "Bearer " + apps.present.access_token };
async function post(path, value, key) {
  const r = await fetch(base + path, {
    method: "POST",
    headers: { ...headers, "Content-Type": "application/json", "Idempotency-Key": key },
    body: JSON.stringify(value)
  });
  if (!r.ok) throw new Error((await r.json()).error.message);
  return r.json();
}
const deck = await post("/v1/decks", { title: "Design review" }, crypto.randomUUID());
const content = await fetch(base + "/v1/decks/" + deck.id + "/content", { headers }).then(r => r.json());
const changes = await post("/v1/decks/" + deck.id + "/edits", {
  base: content.version,
  ops: [{ op: "add_slide", slide: { id: "s_review", notes: "Discuss the design." } }]
}, crypto.randomUUID());

Creation returns HTTP 201 with the deck ID, title, effective role, version and link. Edits return the committed version, change flag and touched slide IDs. Use the same key and exact request bytes when retrying an uncertain write. On a version conflict, read the current deck before preparing a new operation.

People, contacts and Ting

Let the account opt in with PUT /v1/contacts/connection {"connected":true}. This gives Present access to the selected account’s Silicon Contacts address book. GET /v1/people?q= searches saved names, public IDs and previous collaborators. Results include UUID, ID, kind, displayName, pfp and saved trust. Higher-trust matches appear first. Resolve an entered ID or known email with GET /v1/accounts/resolve?q=. Invite a chosen UUID with POST /v1/decks/{id}/access {"to":"ACCOUNT_UUID","role":"viewer"}. An email can also create a pending invitation.

List the address book with GET /v1/contacts. Save or update a contact with POST /v1/contacts {"id":"ACCOUNT_UUID","name":"Design partner","trust":180}. Trust ranges from 1 to 255. Remove a saved contact with DELETE /v1/contacts/{id} using its account UUID. Saved photos use owner-authenticated paths on this API. Disconnect using {"connected":false}.

Shares, mentions, replies, comments, thread resolutions and transfer changes send durable, account-addressed Tings. A Silicon can read its inbox with no hook configured. Present enrolls the receiving account when it signs in. A recipient who wants webhook delivery can configure a local receiver in Silicon Ting with ting webhook http://localhost:3000/ting. Work accounts and teams

Send the selected work account’s Present token to GET /v1/organizations. It returns the account UUID, eligible organizations, memberships and selectable sharing targets. Show settings according to the returned capabilities. GET /v1/organizations/{org} returns permitted teams and members. Use POST /v1/organizations/{org}/actions with a stable idempotency key for authorized settings changes such as {"action":"team_create","name":"Design"}. Organizations integration guide

Grant a role with PUT /v1/folders/{id}/groups {"principal":"team:ORG/TEAM_ID","role":"commenter"}. Build the principal from a returned share target’s type and ID. The same operation works for decks and whole organizations. Set role to null to remove the direct grant. A folder grant reaches its descendants. Present checks current membership, access to Present and resource permissions. A personal sign-in has its own permissions.

Live editing, presentations and files

Open GET /v1/decks/{id}/live with streaming fetch. Apply the initial Yjs sync update, process update and presence events, and send local deltas to /updates. Share a running presentation’s follow URL or use deck content to implement a self-paced view. The library SSE endpoint emits refresh hints. On reconnect, reload the library, send the latest Yjs state vector, and check current access. Wire protocol and resource shapes

Upload raw file bytes with Content-Type and X-Filename to import or attach a file. Exports and slide renders return binary bodies. Limits, errors and recovery

People and contact endpoints accept an offset and a limit of 1–200. Version listing accepts 1–1,000 groups. Search returns up to 50 candidate decks. Library lists return their complete matching scope. JSON request bodies are limited to 4 MiB, presence to 16 KiB and binary uploads to 512 MiB. Present applies upstream service limits, including Accounts lookup limits. Back off after a 429 and honor Retry-After when supplied.

Errors contain {"error":{"code":"…","message":"…","hint":"…"}}. A 401 requires a fresh Present access token or a new sign-in. A 403 indicates insufficient permissions or a required viewer email. A 404 can indicate a resource unavailable to the caller. Retry temporary service failures with backoff. An idempotency key is at most 200 bytes. Reusing it with different input returns 409. If a prior mutation is still pending, a 503 may require reconciling the resource before further changes. Send integration issues through POST /v1/reports with a message and request context. Omit credentials and private deck content.
